# 언론사 주소록 통합 포털

서로 다른 양식의 주소록 파일 4종(데스크 현황 xlsx 2개, 출입기자 현황 xlsx, 통합 docx)을
하나의 웹 화면에서 보기 위한 시스템입니다.

- **메인** — 기존 '주요 데스크 현황' 양식 그대로 매체 × 직책 매트릭스
- **매체명 클릭** — 그 매체의 출입기자 명단이 팝업으로
- **검색** — `매경 산업부장이 누구지?` 처럼 물어보면 바로 답
- **업로드** — 갱신된 파일을 올리면 바뀐 부분만 뽑아 보여 주고, 확인 후 반영
- **이력** — 누가 언제 어느 자리에 있었는지 과거 상태가 그대로 남음

> ⚠️ **이 저장소에 실제 주소록 파일·DB 덤프·전화번호를 커밋하지 마세요.**
> `.gitignore` 로 막아 두었습니다. 원본은 서버의 볼륨에만 보관됩니다.

## 1. 서버에 올리기

> ⚠️ **우분투 서버에서 실행하세요.** 맥에서 실행하면 안 됩니다.
> `ssh ubuntu@<서버주소>` 로 접속한 뒤 진행합니다.

도커가 아직 없다면 먼저 설치합니다 (한 번만).

```bash
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER && newgrp docker
```

그다음 세 줄이면 끝입니다.

```bash
git clone -b claude/media-contacts-web-portal-mtcwwq https://github.com/hongukchung-dot/contacts.git
cd contacts
./deploy.sh
```

`./deploy.sh --install-docker` 로 실행하면 도커 설치까지 스크립트가 대신 해 줍니다.

`deploy.sh` 가 하는 일:

1. `.env` 가 없으면 `.env.example` 을 복사하고 `SECRET_KEY` · DB 비밀번호를 자동 생성
2. Docker 이미지 빌드 후 `db` / `app` / `caddy` / `backup` 컨테이너 기동
3. 스키마 생성 + 매체 사전(42개 매체·별칭) 시드 + 관리자 계정 생성
4. 관리자 비밀번호를 화면에 **한 번만** 출력

### 포트가 이미 쓰이고 있다면

서버에서 이미 다른 서비스가 80·443 을 쓰고 있으면 `.env` 의 포트를 바꾸면 됩니다.
첫 배포 때는 `deploy.sh` 가 충돌을 감지해 자동으로 빈 포트(8080·8443)를 잡아 줍니다.

```bash
HTTP_PORT=8080     # → http://<서버IP>:8080
HTTPS_PORT=8443
```

무엇이 포트를 쓰고 있는지 확인:

```bash
sudo ss -lptn 'sport = :80'
sudo ss -lptn 'sport = :443'
```

이미 nginx 등이 돌고 있다면, 그쪽에 리버스 프록시를 한 줄 추가하는 방법이 더 깔끔합니다.
이 경우 기존 서버의 도메인·인증서를 그대로 쓰게 됩니다.

```nginx
location / {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 60m;
}
```

### 도메인과 HTTPS

`.env` 의 `SITE_ADDRESS` 를 바꾸면 Caddy 가 인증서를 자동 발급합니다.

```bash
SITE_ADDRESS=contacts.example.com   # 인증서 자동 발급 (권장)
SITE_ADDRESS=:80                    # 도메인 없이 HTTP (사내망 전용)
```

단, 인증서 자동 발급은 **`HTTP_PORT=80`, `HTTPS_PORT=443` 이고 DNS A 레코드가
이 서버를 가리킬 때만** 됩니다. 포트를 바꿔 쓰는 상황이라면 위의 nginx 프록시 방식을 쓰세요.
특정 IP에서만 열고 싶으면 `Caddyfile` 의 `@notallowed` 블록 주석을 푸세요.

### 접속이 안 될 때

먼저 서버 안에서 앱이 살아 있는지 확인합니다. `ok` 가 나오면 앱은 정상이고 접속 경로만 문제입니다.

```bash
curl http://127.0.0.1:8080/healthz     # → ok
```

> `curl -I` 는 HEAD 요청이라 `405 Method Not Allowed` 가 정상입니다. 오류가 아닙니다.

그다음 접속 가능한 주소를 확인합니다.

```bash
hostname -I              # 이 서버가 가진 IP 전부
tailscale ip -4          # Tailscale 을 쓴다면 (이 주소가 가장 안전)
sudo ufw status          # 방화벽이 포트를 막고 있지 않은지
sudo ufw allow 8080/tcp  # 막혀 있다면 열기
```

클라우드(AWS·오라클 등)라면 콘솔의 보안 그룹에서도 해당 포트 인바운드를 열어야 합니다.

### 갱신

```bash
git pull && ./deploy.sh
```

### 규칙을 고친 뒤 데이터를 다시 만들기

파싱·매칭 규칙이 바뀌면 이미 쌓인 데이터는 옛 규칙으로 만들어진 것입니다.
**업로드한 원본 파일은 서버에 보관돼 있으므로 파일을 다시 올릴 필요가 없습니다.**

```bash
docker compose exec app python tools/rebuild.py         # 무엇을 할지 먼저 보여 줍니다
docker compose exec app python tools/rebuild.py --yes   # 실제로 다시 만듭니다
```

계정·매체 사전·접속 기록은 그대로 두고 인물·자리·업로드 이력만 새로 만듭니다.
보관본이 없다면 `--from-dir /경로` 로 원본이 있는 디렉터리를 지정하세요.

> ⚠️ 화면에서 손으로 고친 항목은 사라집니다. `--yes` 없이 먼저 돌리면 몇 건인지 알려 줍니다.

### 처음부터 다시 하고 싶다면

`.env` 만 지우면 **DB 비밀번호가 어긋납니다.** PostgreSQL 은 데이터 볼륨을 처음 만들 때
한 번만 계정을 잡기 때문입니다. 자료를 지울 각오가 됐다면 볼륨까지 함께 지우세요.

```bash
docker compose down -v    # -v 가 핵심: DB 볼륨까지 삭제
rm -f .env
./deploy.sh
```

자료를 지키면서 설정만 고칠 때는 `.env` 를 지우지 말고 필요한 줄만 수정한 뒤
`./deploy.sh` 를 다시 돌리면 됩니다.

## 2. 처음 데이터 넣기

**기준일이 오래된 파일부터** 올리세요. 새 파일이 옛 파일을 덮어써야 하기 때문입니다.

```
1) (26-0609) 출입기자 현황.xlsx
2) (26-0609) 주요 데스크 현황(그룹).xlsx
3) (26-0731) 주요 데스크 현황.xlsx
4) (26-0803) 주요 데스크 출입기자 현황.docx
```

웹의 **파일 업로드** 화면에서 하나씩 올리고, 검토 화면에서 내용을 확인한 뒤 반영합니다.
순서를 거꾸로 올려도 안전합니다 — 이미 반영된 파일보다 기준일이 오래된 파일은
자동 반영이 전부 꺼지고 모든 항목이 검토 대상이 됩니다.

### 통합 docx 의 데스크 / 출입기자 구분

`주요 데스크/출입기자` 워드 파일은 매체마다 맨 위에 부장급 데스크가 오고
그 아래에 출입기자가 붙습니다. 다만 **줄 위치가 아니라 직급으로** 가릅니다.

| 직급 | 판정 |
|------|------|
| 부장 · 국장 · 부국장 · 에디터 · 주필 · 대표 | 데스크 |
| 차장 · 팀장 · 기자 | 출입기자 |
| 직급 표기가 없음 | 그 줄의 성격을 따름 (대개 출입기자) |

줄 위치만 보면 배치가 조금만 달라져도 출입기자가 데스크로 잡힙니다.
실제로 그런 오류가 대량으로 났습니다. 직급이라는 값 자체를 기준으로 삼는 편이 안전합니다.

**출입기자는 간부 현황 표의 칸을 차지하지 않습니다.** `산업부 차장`이 산업부장 칸에
들어가는 일을 막기 위한 것으로, 출입기자는 매체 팝업의 부서별 명단에만 나옵니다.

### 엑셀 탭이 여러 개일 때

**모든 탭을 읽습니다.** 탭마다 양식이 달라도(어떤 탭은 데스크 표, 어떤 탭은 출입기자 목록)
각각에 맞는 방식으로 처리합니다. 검토 화면에 **탭별로 몇 명을 읽었는지** 표시되니
빠진 탭이 없는지 확인하세요.

구조를 알아보지 못한 탭은 `0명 / 구조 미인식`으로 표시되고 경고가 붙습니다.
조용히 빠지지 않습니다.

### 올리기 전에 파싱만 확인하고 싶다면

DB를 건드리지 않고 파싱 결과만 출력합니다.

```bash
docker compose exec app python tools/inspect_file.py /path/to/파일.xlsx --full
```

- 읽어 들인 인원 수, 매체 분류
- 사전에 없는 매체 (→ `data/reference/outlets.yml` 에 추가)
- 전화번호가 없는 인원, 해석하지 못한 칸

## 3. 화면 사용법

| 화면 | 하는 일 |
|------|---------|
| 간부 현황 | 매체 × 직책 매트릭스. 분류(종합지/경제지/방송/통신사/전문지) 필터, 엑셀 내려받기 |
| 매체명 클릭 | 데스크 + 부서별 출입기자 팝업. `명단 전체 복사` 로 탭 구분 텍스트 복사 |
| 검색 | 아래 참조 |
| 변경 이력 | 반영된 파일 목록과 항목별 변경 내역 (이전값 → 이후값 + 근거 파일) |
| 파일 업로드 | 업로드 → 변경 검토 → 선택 반영 |
| 직접 입력 | 매체를 고르고 명단을 직접 넣거나 고칩니다 (업로드 권한 이상) |
| 직접 수정 | 팝업의 각 행 오른쪽 `수정` 버튼 |
| 계정 관리 | 계정 생성·비밀번호 재발급·사용 중지, 접속/조회 기록 |

전화번호는 기본으로 가려져 있습니다. **한 번 클릭하면 표시**, **한 번 더 클릭하면 복사**됩니다.
최근 45일 이내에 바뀐 셀은 노란 음영으로 표시됩니다 (`HIGHLIGHT_DAYS` 로 조정).

### 검색 예시

```
매경 산업부장이 누구지?     → 매일경제 · 산업부장 해석 후 즉답
조선일보 테크부              → 해당 부서 인원
산업부장                     → 전 매체 산업부장 목록
김현수                       → 이름으로 조회
010-3121-3417 / 3121-3417   → 번호로 역조회
매일경졔                     → 오타도 유사도 검색으로 보정
```

매체 별칭(`매경`·`한경`·`서경`·`파이낸셜 뉴스` 등)은 `data/reference/outlets.yml` 에서
얼마든지 추가할 수 있습니다.

> ⚠️ **앞부분이 같다고 다른 매체로 이어 붙이지 않습니다.**
> `조선일보 ≠ 조선비즈`, `연합뉴스 ≠ 연합뉴스TV`, `한국경제 ≠ 한국경제TV` 입니다.
> 사전에 없는 매체는 **새 매체**로 등록되고, 이름이 비슷한 매체가 있으면
> "⚠ 조선일보 와 비슷" 처럼 경고가 붙습니다. 잘못 합치는 것보다 훨씬 낫기 때문입니다.
>
> 정말 같은 매체라면 `outlets.yml` 의 해당 매체 `aliases` 에 표기를 넣고
> `tools/init_db.py` 를 다시 돌리면 됩니다.

## 4. 화면에서 직접 넣고 고치기

### 직접 입력 페이지

상단 메뉴의 **`직접 입력`** 에서 매체를 고르면 그 매체의 현재 명단이 나오고,
아래 폼으로 바로 추가할 수 있습니다. 저장해도 화면이 그대로 유지되므로
**여러 명을 이어서 넣기** 좋습니다.

파일에 없는 사람, 파일이 나오기 전에 먼저 알게 된 인사이동 등을 여기서 반영합니다.

### 이메일과 메모

전화번호 외에 **이메일**과 **메모**를 넣을 수 있습니다.

- 이메일 — 화면에서 누르면 메일 쓰기로 이어지고, 검색·엑셀 내보내기에도 포함됩니다
- 메모 — 특이사항·성향·최근 접촉 기록 등 자유 기록. 검색에도 걸립니다

둘 다 사람에 붙는 정보라, 그 사람이 여러 매체·부서에 등록돼 있어도 한 번만 넣으면 됩니다.

### 잘못된 항목 고치기

파일이 항상 정확하지는 않습니다. 한 사람이 두 명으로 잡히거나 직책이 엉뚱하게 붙는 일이
실제로 생깁니다. 매체 팝업이나 직접 입력 페이지의 각 행 오른쪽 **`수정`** 버튼에서
바로잡을 수 있습니다.

### 잘못된 직책 고치기

예) 서울신문 산업부장이 곽소영으로 잡혔지만 실제로는 이경주인 경우 —
곽소영 행의 `수정`을 눌러 **직책 열**을 비우고 구분을 `출입기자`로 바꾸면
간부 현황 표의 산업부장 칸에서 빠집니다.

| 항목 | 뜻 |
|------|-----|
| 직책 열 | 간부 현황 표의 **어느 칸에 놓일지**. 비우면 표에 나오지 않습니다(출입기자) |
| 직책 | 원문 그대로의 표기 (`산업1부장`, `차장` 등). 화면에 그대로 보입니다 |
| 부서 | 팝업에서 출입기자를 묶는 기준 (산업부·테크부 등) |

### 목록에서 빼기 — 두 가지가 다릅니다

| 버튼 | 쓸 때 | 결과 |
|------|-------|------|
| **자리 종료** | 인사이동으로 그 자리를 떠남 | 현재 목록에서 빠지고 **지난 이력에 남음** |
| **잘못된 항목 삭제** | 애초에 잘못 들어온 항목 | 흔적 없이 지움. 그 사람의 자리가 하나도 안 남으면 인물도 정리 |

### 같은 사람이 두 번 등록됐다면 — 합치기

이름을 눌러 **인물 페이지**로 가면 `같은 사람으로 의심되는 항목`이 뜹니다.
이름이나 번호가 같은 인물을 찾아 보여 주고, `이쪽으로 합치기`를 누르면
상대의 자리와 번호 이력이 이쪽으로 모입니다. 완전히 겹치는 자리는 하나만 남습니다.
되돌릴 수 없으니 확인 후 진행하세요.

### 고친 항목은 잠깁니다

손으로 고친 자리에는 ✎ 표시가 붙고 **잠깁니다.** 다음에 올라온 파일이 같은 자리를
바꾸려 하면 자동 반영되지 않고 검토 화면으로 넘어갑니다. 이게 없으면 애써 바로잡은
값이 다음 업로드에 조용히 원복됩니다.

모든 수정·삭제·합치기는 누가 언제 무엇을 바꿨는지 감사 로그에 남습니다.

## 5. 파일이 갱신되면

1. **파일 업로드** 에 새 파일을 올린다 (형식은 자동 판별)
2. 변경 내역이 네 갈래로 정리되어 나온다

   | 유형 | 기본 상태 | 설명 |
   |------|-----------|------|
   | 신규 | ✅ 자동 승인 | 명단에 없던 인물 |
   | 변경 | ✅ 자동 승인 | 번호·직책·부서 변경 |
   | **확인 필요** | ⬜ 검토 | 번호가 1~2자리만 다름 → **오타 의심** |
   | **삭제** | ⬜ 검토 | 이번 파일에서 빠짐 (퇴사·인사이동 or 파일 누락) |

3. 체크한 항목만 반영된다. 체크하지 않은 항목은 반려되고, 원본 파일과 파싱 결과는 그대로 보관된다.

**왜 오타를 따로 잡는가** — 실제 원본 4개 파일을 대조해 보니
서울경제 손철(`…8199` ↔ `…8119`), 이데일리 김정남(`…9879` ↔ `…9876`),
아시아경제 박소연(다른 사람과 같은 번호)처럼 한두 자리만 어긋난 값이 있었습니다.
"최신 파일이 항상 옳다"로 덮어쓰면 이런 오타가 그대로 정답이 됩니다.

같은 파일을 두 번 올리면 내용 해시로 걸러 냅니다.

## 6. 데이터 구조

엑셀을 그대로 테이블로 옮기지 않습니다. 파일마다 열 구성이 다르고(대표·증권부장 유무)
한 칸에 사람이 여러 명 들어가기 때문입니다. **"사람 1명 = 1행"** 으로 정규화합니다.

```
outlet ──< outlet_alias          매체와 별칭(매경 → 매일경제)
person ──< person_phone          인물과 번호 이력
   └────< assignment             ★ 누가·어느 매체·어느 부서·무슨 직책·언제부터 언제까지
source_file ──< source_record    업로드된 원본 파일과 그 파일에서 읽은 원시 행(원문 보존)
change_set  ──< change           업로드 1건이 만든 변경 묶음과 항목별 승인 상태
app_user, audit_log              계정과 접속·조회 기록
```

핵심 세 가지:

1. **삭제하지 않는다.** `assignment` 는 `valid_to` 만 닫아 과거를 남깁니다(SCD Type-2).
   "6월엔 고영득, 8월엔 이윤주"가 자동으로 이력이 되고, 인물 페이지에서 이동 타임라인을 볼 수 있습니다.
2. **매체를 옮겼다고 보려면 이름과 번호가 모두 같아야 합니다.**

   | 상황 | 판정 |
   |------|------|
   | 같은 매체 + 이름 일치 | 같은 사람 (번호가 바뀐 것) |
   | 이름 일치 + 번호 일치 | 같은 사람 (매체 이동) |
   | 번호만 일치, 이름 다름 | **다른 사람** → 확인 필요로 표시 |
   | 이름만 일치, 번호 다름 | **다른 사람** (동명이인) |

   이름만 같으면 같은 사람으로 묶던 초기 규칙 때문에 동명이인이 통째로 다른 회사로
   옮겨간 것처럼 기록되는 문제가 있었습니다. 사람이 많은 출입기자 명단에서 특히 심했습니다.
3. **모든 값에 출처가 붙는다.** `source_record.source_text` 에 원본 셀 문자열이
   그대로 남아 "이 값 어디서 왔지?"를 되짚고, 파싱 규칙을 고쳐 재처리할 수 있습니다.

## 7. 보안

실명 + 개인 휴대전화번호가 수백 건 들어 있는 자료입니다. 기본으로 적용된 것:

- 로그인 필수 (계정별). 미인증 시 어떤 데이터도 노출되지 않음
- 권한 3단계 — `조회` / `조회+업로드` / `관리자`
- HTTPS 자동 (도메인 설정 시), HSTS
- `robots.txt` + `X-Robots-Tag: noindex` 로 검색엔진 색인 차단
- `X-Frame-Options: DENY`, `Cache-Control: no-store`
- 로그인·검색·매체 조회·업로드·반영·내보내기 전부 감사 로그 기록
- 목록에서 번호 마스킹 (클릭 시 표시 — 어깨너머·화면 캡처 노출을 줄이기 위한 것으로,
  로그인한 사용자에게 값 자체를 숨기는 기능은 아닙니다)
- 비밀번호는 argon2 해시, 세션은 서명 쿠키(HttpOnly, 12시간)
- DB 포트는 외부로 열지 않음 (앱 컨테이너에서만 접근)
- 매일 03:00 `pg_dump` 자동 백업, 14일치 보관 (`./backups/`)
  · 시각·보관일수는 `.env` 의 `BACKUP_HOUR` / `BACKUP_KEEP_DAYS` 로 조정
  · 지금 바로 한 번 뜨기: `docker compose exec backup /scripts/backup.sh --once`
  · 복원: `docker compose exec -T db pg_restore -U contacts -d contacts --clean < backups/<파일>.dump`

**직접 챙기셔야 할 것**

- `.env` 파일 권한 (`chmod 600 .env`)
- 서버 방화벽에서 5432(DB) 차단, 22(SSH) 는 필요한 IP만
- `./backups/` 디렉터리를 별도 매체로 주기적으로 옮기기 (같은 서버에만 두면 서버 사고 시 함께 사라집니다)

## 8. 개발

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/pip install pytest httpx

# 파서 테스트만 (DB 불필요)
.venv/bin/python -m pytest tests/test_normalize.py tests/test_parsers.py

# 전체 (PostgreSQL 필요)
export SECRET_KEY=$(openssl rand -hex 32)
export DATABASE_URL_TEST='postgresql+psycopg://contacts:contacts@127.0.0.1:5432/contacts'
.venv/bin/python -m pytest
```

테스트 픽스처(`tests/fixtures/`)는 실제 4개 파일의 레이아웃 특성 —
제목행·기준일행·빈 선행열·한 칸 다중 인물·매체 병합행·`부서 :` 접두어·
구분자 없는 팀원 블록·앞자리 0 누락 번호 — 을 그대로 재현하되
**전화번호는 전부 가짜 값**입니다. `python tests/make_fixtures.py` 로 다시 만들 수 있습니다.

### 구조

```
app/
  ingest/      normalize.py  전화번호 기준 셀 분해, 이름·직책 정규화
               reference.py  매체·직책 사전 매칭
               parsers.py    파일 3종 파서 + 유형 자동 판별
  services/    ingest.py     등록 → 비교 → 승인 → 반영
               matching.py   인물 동일성 판정, 오타 의심 탐지
               directory.py  화면 조회
               search.py     규칙 파서 + pg_trgm 폴백
               auth.py       인증·감사 로그
  templates/   화면
  models.py    스키마
tools/         init_db.py    초기화
               inspect_file.py  DB 없이 파싱 점검
               load_file.py  CLI 적재
data/reference/  outlets.yml  매체·별칭·분류·정렬
                 roles.yml    직책 슬롯·직급·부서 사전
```

### 매체·직책 사전 고치기

새 매체가 나오거나 별칭을 추가하려면 `data/reference/outlets.yml` 을 고치고
`docker compose exec app python tools/init_db.py` 를 다시 돌리면 됩니다(멱등).
사전에 없는 매체가 파일에 나와도 파싱은 실패하지 않고 `미분류` 로 등록된 뒤
검토 화면에 경고로 표시됩니다.

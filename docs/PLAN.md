- **셀 안 다중 인물**: `정 욱(산업부) 010-…-2814  고 재 만(테크부) 010-…-9028` 처럼 한 셀에 2명 이상.

## 3. 제안 아키텍처

```
[구글드라이브 '주소록' 폴더]
        │  (① 웹 업로드  또는  ② 드라이브 자동 폴링)
        ▼
  ┌───────────────────────────────────────────┐
  │ Ingest 파이프라인 (Python)                 │
  │  파일유형 자동판별 → 전용 파서 → 정규화    │
  │  → staging 적재 → 현재본과 diff → 리포트   │
  └───────────────────────────────────────────┘
        ▼ (자동반영 or 승인 후 반영)
  ┌───────────────────────────────────────────┐
  │ PostgreSQL  (인물/매체/직책/스냅샷/이력)   │
  └───────────────────────────────────────────┘
        ▼
  ┌───────────────────────────────────────────┐
  │ FastAPI + Jinja2 웹앱                      │
  │  ·매트릭스 표 ·매체 클릭→기자 팝업          │
  │  ·자연어 검색 ·변경이력 ·업로드 화면        │
  └───────────────────────────────────────────┘
        ▼
  Caddy (HTTPS + 로그인) ← 사용자 브라우저
```

**스택 선정 이유**
- Python: `openpyxl`(xlsx) + `python-docx`(docx) 조합이 이 데이터 파싱에 가장 강력. 한글 정규식 처리도 용이.
- FastAPI + Jinja2 서버렌더링: 화면이 표 2종 + 모달 + 검색 수준 → SPA 불필요, 유지보수 부담 최소.
- Docker Compose: 서버에 파이썬/DB 직접 설치 없이 `up -d` 한 번.
- Caddy: 도메인만 있으면 Let's Encrypt 인증서 자동 발급 + 로그인 게이트.

## 4. 데이터베이스 설계 (핵심 제안)

**엑셀을 그대로 테이블로 옮기지 않는다.** 열이 파일마다 다르고(대표·증권부장 유무), 셀 안에 사람이 여러 명이라 확장이 막힌다.
→ **"사람 1명 = 1행"의 인물 중심 모델 + 스냅샷/이력 분리**로 설계한다.

### 4.1 테이블

| 테이블 | 역할 | 주요 컬럼 |
|--------|------|-----------|
| `outlet` | 매체 마스터 | id, 정식명, 분류(종합지/경제지/방송/통신/전문지), 표시순서 |
| `outlet_alias` | 매체 별칭 | outlet_id, alias (`매경`,`조선`,`파이낸셜 뉴스` …) |
| `person` | 인물 마스터 | id, 성명(정규화), 성명(원문) |
| `phone` | 연락처 | person_id, 번호(정규화 `01012345678`), 유효기간 |
| `role_type` | 직책 사전 | code(`산업부장`), 표시명, 계층(대표/국장/부장/차장/기자), 정렬순서 |
| `assignment` | **핵심**: 누가·어느 매체·무슨 부서·무슨 직책 | person_id, outlet_id, 부서, role_type, 구분(데스크/출입기자), 유효시작, 유효종료(NULL=현직) |
| `source_file` | 업로드된 파일 1건 | id, 파일명, 유형, 기준일, 해시(중복 방지), 업로드시각 |
| `source_record` | 파일에서 뽑은 원시 행 | source_file_id, 원문셀, 파싱결과(JSON) |
| `change_log` | 변경 이력 | 대상, 변경유형(신규/수정/삭제/이동), 이전값, 이후값, 근거 source_file_id, 승인자 |
| `app_user` | 로그인 계정 | id, 아이디, 비밀번호해시, 권한(조회/편집) |

### 4.2 설계 포인트

1. **`assignment`는 삭제하지 않고 `유효종료`만 채운다(SCD Type-2).**
   → "6월엔 고영득, 8월엔 이윤주"가 자연스럽게 이력으로 남고, "3개월 전 매경 산업부장" 조회도 가능.
2. **인물 동일성 판정은 `전화번호 → 성명+매체 → 성명` 우선순위.**
   전화번호가 가장 안정적이지만 위 1.2처럼 재사용 사례가 있으므로 단독키로 쓰지 않고 **점수 매칭**.
3. **`source_file.해시`로 같은 파일 재업로드를 자동 차단.**
4. **파일별 신뢰도 가중치**를 둔다(예: 출입기자 명단은 기자 정보에, 데스크 현황은 데스크 정보에 우선권). 기준일 최신 + 항목별 권위 파일 조합으로 최종값 결정.
5. 원본 셀 텍스트(`source_record.원문셀`)를 반드시 보존 → 파싱 오류 시 재처리 가능, "이 값 어디서 왔지?" 추적 가능.

### 4.3 DB 엔진 권장

- **권장: PostgreSQL 16 (Docker)**
  - `pg_trgm` 확장으로 한글 부분일치·오타 허용 검색이 강력 (`매일경졔` → `매일경제`).
  - 이력 테이블이 계속 쌓여도 안정, 동시 접속·다중 편집 안전.
  - `pg_dump` 일일 백업 cron 구성이 단순.
- 대안: SQLite + FTS5 — 설치가 아예 없고 파일 1개 백업이라 더 가볍다. 사용자가 1~2명이고 서버 자원을 아끼고 싶다면 충분.
- **비권장: 구글 시트를 DB로 계속 쓰기** — 이력·중복·충돌 관리가 안 되고, 이번 요구사항(자동 diff)이 성립하지 않음.

## 5. 자동 업데이트(diff) 동작 방식

1. 파일 업로드(또는 드라이브에서 신규 파일 감지)
2. 파일 유형 자동 판별 → 해당 파서 실행 → 정규화된 `assignment` 후보 생성
3. 현재 DB 상태와 비교 → 4종 분류
   - `신규` 등록되지 않은 인물/직책
   - `변경` 번호 변경, 직책 변경, 부서 이동
   - `삭제` 최신 파일에서 사라짐(퇴사·출입 해제 추정)
   - `충돌` 다른 파일이 더 최신인데 값이 다름 / 번호 1~2자리만 다름(오타 의심)
4. **변경 미리보기 화면**에 표로 제시 → `전체 승인` 또는 항목별 체크 후 반영
   - 기본값: 신규·단순변경은 **자동 반영**, 삭제·충돌은 **승인 필요** (오타로 인한 데이터 훼손 방지)
5. 반영 결과는 `change_log`에 기록, 메인 화면에서 **최근 변동분 음영 표시** (기존 엑셀의 "전월 변동 음영" 관행 그대로 계승)

## 6. 화면 구성

### (1) 메인 — 주요 간부 현황 (기존 '주요 데스크 현황' 양식 계승)
- 행 = 매체, 열 = 대표 / 편집국장 / 산업부장 / 경제부장 / 증권부장 / 사회부장 / 정치부장 / 논설실장 / 온라인부장 / 법조팀장
- 분류별 섹션: 종합지 · 경제지 · 석간·통신 · 방송 · 전문/영자지
- 셀: `이름 (직책) 전화` + 전화 클릭 시 복사, 모바일에선 `tel:` 링크
- 최근 변경 셀은 노란 음영 + 툴팁으로 "8/3 파일 반영, 이전값 ○○○"
- 상단 필터: 분류 / 직책 / 검색어, 우측 상단 `엑셀 내보내기`

### (2) 매체명 클릭 → 출입기자 팝업
- 모달: 매체 로고성 헤더 + 데스크 라인 + 출입기자 표(이름·직급·부서·연락처)
- 부서(산업부/테크부/IT과학부 등)별 그룹핑, 전체 복사 버튼
- 하단에 "기준: (26-0803) 파일" 출처·기준일 표기

### (3) 검색 — "매경 산업부장이 누구지?"
2단 구조로 구현 (외부 API 없이 서버 내에서 즉시 응답):
1. **규칙 파서**: 문장에서 매체 별칭 + 직책 키워드 추출 → DB 직조회 → 답변 카드
   (`매경 산업부장` → 매일경제 정욱 산업부장 010-****-2814 [프로필 열기])
2. **유사도 검색 폴백**: 규칙 미매칭 시 `pg_trgm`으로 이름·매체·직책 통합 검색 결과 목록
- 지원 질의 예: `매경 산업부장`, `조선일보 테크부`, `010-****-1092 누구야`, `김현수`, `산업부장 전체`

### (4) 업로드 & 변경이력
- 드래그앤드롭 업로드 → 변경 미리보기 → 승인
- 이력 페이지: 날짜별 변경 목록, 인물별 이동 타임라인

## 7. 보안 (중요)

이 데이터는 **수백 명의 실명 + 개인 휴대폰 번호**다. 인증 없는 공개 웹페이지로 두면 사고 위험이 매우 크다. 기본 설계에 다음을 포함한다.

- 로그인 필수(계정/비밀번호), 미인증 시 어떤 데이터도 노출 없음
- HTTPS 강제 (Caddy 자동 인증서). 도메인이 없으면 IP + 자체 인증서 또는 방화벽 IP 화이트리스트
- 검색엔진 색인 차단(`robots.txt`, `X-Robots-Tag`)
- 접속·조회·다운로드 로그 기록
- 전화번호 기본 마스킹 + '보기' 클릭 시 노출(옵션)
- 원본 파일·DB 덤프는 `.gitignore`로 **저장소에 절대 커밋 금지**
- 일 1회 `pg_dump` 자동 백업 + 7일 보관
